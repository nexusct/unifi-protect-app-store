How to implement Nexus Vision on UniFi Protect

From a GPU appliance to working AI alerts on your existing cameras: hardware, UniFi setup, zone mapping, alert routing, and writing your own functions. Setup time depends on stream count, camera placement, and calibration needs.

1 · Hardware & GPU sizing 2 · UniFi Protect setup 3 · Install the platform (Docker) 4 · Map cameras and zones 5 · Pick functions & tune thresholds 6 · Route alerts (NOC, Slack, Teams, email) 7 · Go-live checklist & tuning window 8 · Write your own function

1 · Hardware & GPU sizing

Everything runs on one appliance on your network. Size it by stream count — not camera count, since most functions only need a few cameras each.

Streams with AIApplianceNotes
1–6NVIDIA Jetson Orin Nano/NXSits next to the NVR, fanless, ~15W
6–20Desktop with RTX 4060–4070 class GPUTypical single-site sweet spot
20–40Server with L4 / RTX 4080+ classCampus, multi-building, MDF install
40+Multiple appliancesSplit by building; each runs its own container
  • The GPU-load dial: VISION_FRAME_INTERVAL (default 1 frame/second per stream). Most functions don't need more. Drop to 2.0s to double capacity; raise to 0.5s for fast scenes (drive-thru, conveyor).
  • Network: the appliance needs to reach the Protect console (API) and each camera's RTSP port (7441). No internet access is required after model download.
  • Storage: alert snapshots + clips are small; 50GB is generous. The NVR remains the recording system of record — we don't duplicate it.
Rule of thumb: if the site already runs UniFi Protect happily, the AI appliance is a drop-in. Nothing about the existing camera or network config changes.

2 · UniFi Protect setup

Enable RTSP per camera

Protect console → Cameras → [camera] → Settings → Advanced → RTSP. Enable it and copy the rtsps:// alias URL. Use the lowest-resolution stream that still shows the target clearly; 720p is often sufficient and reduces GPU load versus higher resolutions.

Create a read-only service account

Console → Settings → Users → Add User → local-only, Viewer role. This is what the platform uses to discover cameras and pull events. Keep it read-only; the platform never writes to Protect.

UniFi Access (optional, unlocks correlation functions)

For tailgating, vendor windows, and door-event correlation: create a local Access admin token and note the door names — they map to camera zones in step 4.

docker compose --profile gpu up -d

# verify
curl http://localhost:8090/health
curl http://localhost:8090/streams    # every camera should show up: true

First boot downloads model weights (~200MB). After that the appliance can run fully offline.

4 · Map cameras and zones

Every function reads its geometry from sites.yaml. Zones are polygons in normalized coordinates (0.0–1.0 across the frame), so they survive resolution changes.

cameras:
  - id: "dock-east"
    name: "Dock East"
    # rtsp: omitted = auto-discovered from Protect by camera name
    functions: ["fire-exit-blocked", "truck-turn-time"]
    zones:
      exit: [[0.55, 0.30], [0.95, 0.30], [0.95, 0.90], [0.55, 0.90]]
      yard: [[0.05, 0.20], [0.50, 0.20], [0.50, 0.95], [0.05, 0.95]]

Drawing zones without a special tool

  • Open the camera's live view in Protect, screenshot it.
  • Drop the image in any browser-based polygon tool (or PowerPoint) and read corner positions as fractions of width/height. Top-left of frame is [0,0], bottom-right is [1,1].
  • Zones should hug the floor plane — draw where feet/wheels touch the ground, not up the wall. Detection points are bottom-center of each bounding box.
Onboarding shortcut: on a managed subscription, send us the camera screenshots and we return a finished sites.yaml. Zone mapping is the only step that benefits from experience.

5 · Pick functions & tune thresholds

Assign functions per camera in sites.yaml. Tune per-site thresholds in function_settings:

function_settings:
  queue-length:
    max_length: 4          # people before alert
    hold_seconds: 30       # must stay true this long (kills blips)
  after-hours-activity:
    closed_hours: [20, 6]  # 8pm–6am
  • hold_seconds / hold_ms exist on most detectors — they are your false-alarm budget. Start with defaults, tighten after the first week.
  • Alerts can carry a snapshot (unless the camera is in a privacy zone), so tuning can use real examples rather than guesswork.
  • Domain-weight functions (weapon, PPE, smoke, ALPR) ship with a weights path in config — drop the provided .pt file into models/.

Dedup is built in: a repeating condition fires once per dedup window (default 10 minutes), not once per second.

7 · Go-live checklist & tuning window

  • /streams shows every camera up: true with retries not climbing
  • Walk one real scenario per function (stand in the queue zone, block the exit with a box, cross the counting line)
  • Confirm one alert arrives at each destination with a readable snapshot
  • Set the dedup windows and quiet hours for the site
  • Week one: expect one threshold pass per function. That's normal — it's calibration, not failure.

8 · Write your own function

One file in src/marketplace/functions/. The loader validates the manifest and adds it to the storefront catalog automatically.

from marketplace.contract import MarketplaceFunction, boxes_of, in_zone

MANIFEST = {
    "id": "my-function",
    "name": "My Function",
    "tagline": "What it does in one honest sentence.",
    "category": "People & Safety",   # see contract.CATEGORIES
    "tier": "starter",               # starter | pro | enterprise
    "requires_gpu": True,
    "config_schema": {"zone": "polygon — watch area"},
}

class Function(MarketplaceFunction):
    def process(self, camera, frame, ts, ctx):
        zone = (camera.get("zones") or {}).get("watch")
        if not zone:
            return
        for (cls, cx, cy, *rest, tid) in boxes_of(frame, classes=[0]):
            if in_zone(cx, cy, zone):
                ctx.alerts.fire(site=ctx.site, camera=camera,
                                detector=MANIFEST["id"], title="Person in zone",
                                detail="...", frame=frame)
  • boxes_of(frame, classes=[...]) — tracked detections (0 = person; 2/5/7 = car/bus/truck). tid is a persistent track ID.
  • in_zone, crossed_line, ZoneTracker — the geometry helpers every catalog function uses.
  • ctx.alerts.fire() handles severity, dedup, snapshots, and routing. You never write alert plumbing.
  • Pose keypoints (falls, bed-exit, aggression) come from model("yolov8n-pose.pt") — see src/detectors/fall.py for the pattern.
The honest rule: every function in the catalog solves a problem a business is already paying for. If yours does too, it belongs in the marketplace — pull requests welcome.
